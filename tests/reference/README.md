# Reference data used by the solver tests

## Why not live JBM output?
JBM Ballistics retired its online trajectory calculator (the old `cgi-bin/jbmtraj` URL now
redirects to an app landing page), so fresh JBM tables could not be generated for this project.
The tests use the best available substitutes instead:

| Source | What it is | Used for |
|---|---|---|
| `js/solver/dragTables.js` | G1 and G7 Cd-vs-Mach tables downloaded from JBM (`/downloads/mcg1.txt`, `mcg7.txt`), originally BRL / R. L. McCoy | The solver's drag functions |
| `gehtsoft/g1_*.txt`, `gehtsoft/g7_nowind.txt` | Full 50-yd trajectory tables to 1000 yd, in JBM's column layout (Range, Drop in/MOA, Windage in/MOA, Velocity, Mach, Energy, Time). The repo describes them as "generated by an independent 3DOF model". | Drop, windage, velocity, energy, TOF and Mach at every row |
| `gehtsoft/g1_nowind_up_supersonic.txt` | +10° uphill shot from Hornady's 3DOF calculator | Shooting angle |
| `gehtsoft/be_coriolis_*.txt` | Ballistic Explorer runs at lat ±45°, east/west | Coriolis directions and baseline |
| `solver.test.js` (PBC_CASES) | Checkpoints from py-ballisticcalc `tests/test_trajectory.py` (lineage: gehtsoft/JBM) | One G1 and one G7 (with spin drift) case |

The `gehtsoft/*.txt` files come from
[gehtsoft-usa/BallisticCalculator1](https://github.com/gehtsoft-usa/BallisticCalculator1)
(`BallisticCalculator.Test/resources`, LGPL-2.1) and are copied unmodified.

## Coriolis note
Ballistic Explorer uses the flat-fire approximation Ω·sinλ·X·t for horizontal Coriolis drift.
This solver integrates the full −2Ω×v acceleration with drag relative to air that rotates with the
Earth. That gives about 15–20% less drift for a bullet that slows down a lot. The two agree exactly
in the drag-free limit, which is what the test checks. The Ballistic Explorer files are only used
to check directions.

## If you can get real JBM output
Add a file in the same `;`-separated format (see `loadGehtsoft.js`) and add its name to
`REFERENCE_CASES` in `tests/solver.test.js`.
